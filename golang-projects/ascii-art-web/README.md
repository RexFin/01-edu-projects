# Ascii-Art-Web-Stylize

ASCII Art Web Stylize - это веб-приложение на языке Go, которое позволяет преобразовывать обычный текстовый ввод в графические надписи, состоящие из символов ASCII. Проект представляет собой полноценную интерактивную веб-версию консольного генератора ASCII-арта с современным, адаптивным и интуитивно понятным пользовательским интерфейсом (UI).

## ​Основные возможности:

- **​Интерактивный веб-интерфейс**: Полноценное клиент-серверное приложение с графической формой для ввода текста.

- **​Динамический выбор баннеров:** Сервер автоматически сканирует доступные шрифты в системе и формирует список в выпадающем меню. Поддерживаются три классических стиля: standard, shadow и thinkertoy.

- **​Поддержка многострочного ввода:** Приложение корректно обрабатывает переносы строк, позволяя генерировать масштабные текстовые блоки.

- **​Безопасность и валидация:** Встроенные проверки на стороне сервера защищают приложение от некорректных запросов и символов, не входящих в кодировку ASCII.

## Внешний вид (Экспериментальный дизайн)

Мы решили отойти от скучных белых страниц и сделать интерфейс, которым просто приятно и приятно пользоваться. Дизайн создавался в стиле старыми консолями, ретро-играми и космической атмосфере.

Вместо корпоративного стиля или же минималистичного стиля мы собрали что-то по типу "космический дизайна":

- **Атмосферный визуал:** Глубокий темно-синий фон, на котором "парят" неоново-бирюзовые ASCII-символы. Выглядит стильно :)
- **Ретро UI:** Весь интерфейс упакован в центральное полупрозрачное окно. Мы использовали пиксельные ретро-шрифты, пунктирные линии-разделители и минималистичные элементы управления. Нету выпадающих списков, только стрелочки `<` STANDARD `>` для переключения баннеров.

## Implementation Details: Algorithm

​Ядром системы является функция `GenerateAscii`, которая преобразует обычный текст в графический формат ASCII с использованием выбранного файла-баннера.

### 1. ​Пошаговый алгоритм работы:

- **Чтение файла шрифта:** На основе переданного имени баннера (standard, shadow, thinkertoy) программа считывает соответствующий файл `.txt` из директории `banners/`.
- **Парсинг строк шаблона:** Содержимое баннера разбивается на массив строк. Для баннера thinkertoy дополнительно обрабатываются символы возврата каретки (`\r\n`), приводя их к стандартному `\n`.
- **Обработка входных данных:** Введенный пользователем текст разбивается по символу новой строки (`\n`). Если встречается пустая строка, в итоговый буфер сразу добавляется перенос строки.
- **Вычисление позиции символа (Матричный рендеринг):** Каждая строка ASCII-символа в файлах баннеров имеет фиксированную высоту в 8 строк, разделенных пустыми строками. Для каждого печатного символа программа вычисляет его стартовый индекс в массиве по формуле:

$$ start = (char - 32) \times 9 + i $$

> где 32 - ASCII-код первого доступного символа (пробел), 9 - размер блока символа (8 строк графики + 1 пустая строка-разделитель), а i - текущая выводимая строка символа (от 1 до 8)

- **Сборка результата:** Строки собираются построчно для каждого слова с использованием оптимизированного буфера `strings.Builder`.

### 2. Сложность алгоритма:

- **​Временная сложность:** O(N \times L), где N - количество символов во входном тексте, а L - высота символа (в данном случае фиксированная константа 8). Таким образом, сложность линейна O(N).
- **​Пространственная сложность:** O(M + N \times 8), где M - размер файла баннера, загружаемого в память, а N \times 8 - память под итоговую строку.

## Error Handling (Status Codes)

​В проекте реализована строгая обработка ошибок на двух уровнях: валидация данных и системные сбои. Приложение безопасно обрабатывает исключения, не допуская падения (crash) сервера.

1. **​200 OK** - арт успешно сгенерирован и отображен на странице.

2. **​400 Bad Request:** Возвращается, если пользователь отправляет пустую форму или вводит символы, не входящие в стандартную таблицу ASCII (проверка через `validators.IsAscii`).

3. **​404 Not Found / Banner Not Found:** Если пользователь пытается перейти по несуществующему URL (например, `/about`), `HomeHandler` возвращает ошибку 404. Если запрашиваемый файл баннера отсутствует на сервере, функция проверяет ошибку через `os.IsNotExist(err)` и возвращает статус 404 с понятным описанием. 

4. **405 Method Not Allowed:** `AsciiHandler` строго проверяет метод запроса. Если отправить GET вместо POST на маршрут `/ascii-art`, сервер заблокирует запрос.

5. ​**500 Internal Server Error:** Вызывается при критических ошибках на стороне сервера, таких как:

 - ​Повреждение или отсутствие HTML-шаблона `templates/index.html` при парсинге.
 - Ошибки чтения файловой системы, не связанные с отсутствием файлов.

## HTTP endpoints

### **​1. Главная страница:**

**Метод: GET**

1. **​Маршрут:** `/`

2. **​Описание:** Отображает начальную веб-страницу приложения. Сервер автоматически сканирует директорию с баннерами и динамически заполняет выпадающий список доступных шрифтов.

3. **Параметры запроса:** Отсутствуют.

4. **​Возвращаемые статусы:** `200 OK` - страница успешно сгенерирована и отправлена пользователю и `404 Not Found` - возвращается в случае, если пользователь запрашивает любой другой путь, отличный от корня (например, /invalid-page).

### **2. Статические файлы (CSS):**

**​Метод: GET**

1. **​Маршрут:** `/static/`

2. **​Описание:** Стандартный обработчик Go (`http.FileServer`), предоставляющий доступ к кастомным таблицам стилей (`style.css`) для оформления веб-интерфейса.

### ​**3. Генерация ASCII-арта:**

**​Метод: POST**

1. **​Маршрут:** `/ascii-art`

2. **​Описание:** Принимает данные из отправленной формы, проверяет их валидность, запускает алгоритм генерации графического текста и возвращает пользователю ту же страницу, но уже с готовым результатом в блоке предварительного просмотра.

3. **Параметры запроса (Form Data):** `​text` (строка, обязательное) - текст, который необходимо преобразовать и `​banner` (строка, обязательное) - название выбранного шрифта (например, standard).
